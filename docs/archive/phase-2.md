# Phase 2: evidence, search, and bounded graphs

The Go worker now indexes approved files after immutable GitHub capture. It stores deterministic, line-addressable text chunks in PostgreSQL and exposes exact/lexical search plus a read-only source viewer. Search and evidence endpoints check the requested repository and snapshot before reading indexed data. The inventory distinguishes analyzed, pending, excluded, unsupported, and failed artifacts. An analyzed file is searchable; it is not a claim that the tool understands its runtime behavior.

Go syntax extraction uses the standard AST parser in a short-lived subprocess with a five-second per-file limit and no application credentials in its environment. Parse failure leaves the file searchable and reports syntax failure for that artifact. All other readable languages currently receive text indexing and explicit syntax/semantic/framework capability gaps. The common evidence and search model is language independent; equal parser depth is not claimed. Paths and folders alone never establish a runtime connection.

Go declarations and unambiguous same-package direct calls become symbol nodes and resolved call edges. The graph endpoint keeps visited nodes, preserves back-edges, and limits traversal to six hops, 200 nodes, and 20 outgoing edges per node within a ten-second request budget. It reports truncation. Method dispatch, interfaces, cross-language events, and deployment wiring remain unresolved unless supported by a future adapter or imported semantic evidence.

A `.scip` protobuf can be uploaded for an existing ready snapshot. The importer accepts a document only if its embedded text exactly matches an approved captured file and the file hash agrees with the inventory. Missing-text, stale, excluded, and unsafe-path documents are skipped. Accepted definition and reference occurrences are stored as snapshot-scoped symbols and relations. The importer does not trust external hover documentation as source evidence. Re-upload replaces only prior SCIP facts for that snapshot. A file with no matching documents is rejected without replacing prior import.

The default profile performs no model requests. A local OpenAI-compatible embedding endpoint or an explicitly enabled cloud profile can create vectors on a separate user action. The hosted adapter uses `text-embedding-3-small` and validates 1,536 returned dimensions, as described in [official OpenAI documentation](https://developers.openai.com/api/docs/guides/embeddings). Cloud access requires both installation mode and repository opt-in; every request passes the privacy gateway and repeats the content scan. There is no cloud fallback when a local provider fails. Vectors are namespaced by provider, model, dimensions, and source content hash. Vector search is exact over the selected snapshot and embedding space; approximate indexes and hybrid rank fusion are not shipped yet. One indexing request is limited to 5,000 chunks. The default installation has no configured provider, so semantic search is visibly unavailable.

For the current API, `GET /v1/repositories` lists recent GitHub snapshots. A ready snapshot supports `/coverage`, `/capabilities`, `/search?q=...`, `/symbols?q=...`, `/graph?symbol_id=...`, and `/evidence/{evidenceId}`. `POST /index` reindexes an existing snapshot, `POST /scip` accepts `application/octet-stream`, and `POST /embeddings` accepts `{"provider":"local"}` or `{"provider":"cloud"}` when configured and authorized. Search defaults to exact/lexical; `mode=semantic&provider=local|cloud` selects vector retrieval. Session and CSRF requirements are the same as capture. These endpoints return evidence, not synthesized answers.

Verification on Windows with Linux Docker containers: Go tests and vet, frontend production build, Phase 0 schema checks, and Compose build/start passed. A public `golang/example` snapshot indexed 69 readable files; 36 had Go syntax extraction, while other artifacts retained explicit capability limits. Exact/lexical search, symbols, a bounded graph, and a synthetic SCIP upload matching a public snapshot were exercised through the API. A reindex collision found during live testing was fixed with a natural source-range upsert; subsequent jobs completed and reindexing retained imported SCIP symbols. A fresh GitHub capture, search result, source citation, and SCIP symbol survived a PostgreSQL restart. Cross-repository evidence and graph requests returned 404; a stale SCIP upload returned 422; cloud embedding and semantic search remained unavailable in strict-local mode. A rolled-back PostgreSQL transaction verified vector insertion and similarity SQL without leaving a synthetic vector. The synthetic excluded marker was absent from searchable evidence. Cycle, high-fan-out, depth-limit, malformed-Go, SCIP range/path, privacy, and provider-failure unit tests pass. Strict-local mode was used for live tests; no cloud provider call or key was used.

The technical onboarding overview, OKF rendering, interactive questions, JavaScript/TypeScript/Python/Java syntax packs, framework-specific edges, hybrid rank fusion, and multi-platform runtime matrix remain for later work. Static evidence does not prove that a declared deployment ran successfully.
